# Data Model: Isolated Agent Editing Runtime

## Editing Session Request

The trusted caller's immutable request to run one registered agent against one exact repository
revision.

| Field | Type | Validation |
| --- | --- | --- |
| `repositoryRoot` | absolute path | Existing local Git worktree resolved by the trusted caller; never forwarded to the container |
| `revision` | commit object ID | Resolves to one commit before any session resource is created |
| `task` | string | Non-empty, bounded UTF-8 text; treated as untrusted agent input |
| `runtimeProfileId` | string | Must resolve in the in-process trusted registry |
| `declaredProjectCommands` | string array | Bounded task context written to the task document; not an enforced OS command allowlist and never interpolated into a host shell |
| `limits` | Session Limits | Every value must fall within configured minimum and maximum bounds |
| `inspectionTimeoutMs` | integer | Positive and within the configured inspection bound |

The request contains no raw Docker flags, image reference, mount source, network name, shell string,
or credential value.

## Session Limits

Finite resources selected by the trusted caller within repository-defined bounds.

| Field | Meaning |
| --- | --- |
| `wallClockMs` | Overall agent execution deadline |
| `stopGraceMs` | Graceful stop interval before force removal |
| `memoryBytes` | Hard container memory and memory-plus-swap limit |
| `cpuCount` | Fractional CPU quota |
| `pids` | Maximum container process count |
| `diagnosticBytes` | Maximum captured stdout plus stderr before sanitization |

## Agent Runtime Profile

A trusted, code-registered execution profile. It is a dependency of the session service, not a
user-serializable request body.

| Field | Type | Validation |
| --- | --- | --- |
| `id` | string | Stable unique identifier |
| `imageReference` | string | Immutable `name@sha256:...` digest or `sha256:...` local image ID; tags and implicit `latest` rejected |
| `argv` | string array | Non-empty direct argv; no shell wrapper generated by FlowProof |
| `environment` | key/value map | Fixed non-secret allowlist; excludes inherited host environment and credentials |
| `workingDirectory` | literal | `/workspace` |

The registered argv reads the task document from `/run/flowproof/task.json`. This feature defines no
credential provider, secret mount, or inherited authentication environment.

## Disposable Editing Workspace

A session-owned standalone Git clone outside the original repository.

| Field | Meaning |
| --- | --- |
| `sessionRoot` | Unique OS-temp directory owned by this session |
| `workspacePath` | Standalone clone mounted at `/workspace` |
| `baselineCommit` | Exact resolved commit checked out detached |
| `taskFilePath` | Bounded session-owned `task.json`, mounted read-only at `/run/flowproof/task.json` |
| `createdPaths` | Exact manifest of paths eligible for cleanup |

### Workspace invariants

- The clone uses no hardlinks or Git alternates.
- It has no remote URL or configuration value containing the original repository path.
- It is the only writable host bind mount visible to the agent.
- The task document contains only the bounded task and declared project-command context; callers do
  not choose its host path or container mount target.
- Cleanup may remove only paths recorded in `createdPaths` beneath `sessionRoot`.

## Editing Session

The lifecycle owner coordinating preparation, container execution, inspection, and cleanup.

| Field | Meaning |
| --- | --- |
| `id` | Generated opaque session identifier used in labels and diagnostics |
| `phase` | Current lifecycle phase |
| `containerId` | Exact Docker ID after successful creation |
| `startedAt` / `endedAt` | Monotonic timing anchors plus serialized bounded durations |
| `terminalSelection` | First execution terminal cause selected atomically |
| `finalization` | Shared idempotent promise used by every exit path |

### Lifecycle states

```text
requested
  -> preparing
  -> starting
  -> running
  -> stopping
  -> inspecting
  -> cleaning
  -> finished
```

Startup may move from `preparing` or `starting` directly to `cleaning`. Completion, non-zero exit,
timeout, and cancellation move from `running` to `stopping`. A process that already exited may skip
the stop operation but not inspection or cleanup. Every path ends in `finished` with a result, even
when cleanup is incomplete. A `failed` cleanup result is a terminal containment failure, not a
successful acceptance case.

### Race rules

- Only the first execution terminal cause is authoritative.
- Repeated cancellation and cleanup calls are idempotent.
- Final inspection starts only after the container process is no longer running.
- Result resolution waits for cleanup and the original-repository integrity check.

## Editing Session Result

The immutable sanitized result returned to the trusted caller.

| Field | Type | Meaning |
| --- | --- | --- |
| `sessionId` | string | Correlates lifecycle operations without exposing a path |
| `executionOutcome` | enum | `completed`, `failed`, `timed_out`, `cancelled`, or `startup_failed` |
| `exitCode` | integer or null | Agent exit code when one exists |
| `signal` | bounded string or null | Normalized process signal when observable |
| `durationMs` | integer | Total bounded session duration |
| `diagnostic` | string | Bounded, sanitized summary only |
| `inspection` | Inspection Summary or null | Non-authoritative bounded metadata from the trusted inspector |
| `cleanup` | Cleanup Result | Complete/recovered/failed status and coded bounded details |
| `runtime` | Runtime Summary | Profile ID and immutable image reference, no credential or raw argv |

The result has no diff, file contents, prompt transcript, raw stdout/stderr, credential, host path,
candidate status, replay status, gate status, or verification verdict.

## Inspection Summary

A bounded, non-authoritative value returned by the fixed trusted inspector during the inspection
window. The first implementation uses only fixture-observable counts and command status. It uses
`lstat`, never follows symlinks or reads special files, verifies resolved parents remain under the
session root, and never runs repository-controlled commands or trusts modified Git configuration,
hooks, or attributes. It must be JSON serializable, size bounded, sanitized, and unable to change
`executionOutcome`.

## Cleanup Result

| Field | Type | Meaning |
| --- | --- | --- |
| `status` | enum | `complete`, `recovered`, or `failed` |
| `containerRemoved` | boolean | Exact owned container no longer exists |
| `workspaceRemoved` | boolean | Session root no longer exists |
| `originalRepositoryUnchanged` | boolean | Complete pre/post integrity snapshot matches |
| `reasonCode` | bounded enum or null | Stable cleanup failure category, never raw tool stderr |
| `remainingOwnedResources` | bounded enum array | Empty for `complete`/`recovered`; exact owned resource categories still present for `failed` |

`recovered` records that a bounded retry restored the same no-residue invariant as `complete`.
`failed` records incomplete final restoration and is not an acceptance success. Neither status
erases the preceding execution outcome.
